# Commit

One script does the mechanical work; you supply the message and report the
result. Do not improvise staging or commit commands — run the script.

## Rules

- **Stage everything by default.** The script runs `git add -A`, not
  `git add <paths>`. Other agents, the IDE, and the user's own edits are part of
  the working tree; the request covers all of it. Never assume only this
  session's files matter.
- **Screen before committing.** The script refuses to commit when the staged
  index contains credentials, tokens, private keys, `.env` files, dumps, scan
  output, logs, caches, large binaries, or conflict markers — even when they are
  not covered by `.gitignore`.
- **Plain, human messages.** Imperative mood, no trailers, no "generated by"
  lines, and no mention of the assistant, model, or tooling that produced the
  change. The script rejects such wording. A reader must see ordinary project
  history.
- **No identity changes.** Keep the repository's configured author/committer;
  the script never passes `--author`.
- **One commit per request** unless the user asks to split the work.
- **Never push, amend, rebase, or force-push** unless the user explicitly asks.
- **Never bypass checks.** No `--no-verify`; if a hook fails, fix the cause.

## Workflow

### 1. Write the message

Subject line:

- Imperative mood: "Add DNS sweep retries", not "Added"/"Adds".
- At most 72 characters, no trailing period, no emoji.
- Say what changed; when useful, the body carries the reasoning.

Body (optional, wrapped at 72 columns): one short paragraph or 2–4 bullets
covering motivation and notable trade-offs. Skip boilerplate restating the diff.

Match the prevailing style in `git log -5 --oneline` (this repo uses short
subjects, sometimes with a release prefix such as `10.28`); never invent a
version number. Do not add authorship trailers, a co-author line for the
assistant, tool or model names, or "Generated with ..." — not in the message and
not in the committed files.

### 2. Run the commit script

From the repository root:

```bash
# Optional: inspect first — stages and screens, commits nothing.
bash .agents/skills/commit/scripts/commit.sh --dry-run

# Commit.
bash .agents/skills/commit/scripts/commit.sh \
  -m "Add DNS sweep retries" \
  -m "Retry NS lookups on transient resolver timeouts."
```

The script is deterministic. It, in order:

1. verifies a repository, a configured identity, a branch (not detached), and no
   merge/rebase/cherry-pick in progress;
2. stages all working files with `git add -A`;
3. screens the index with `scripts/preflight.sh` (sensitive filenames,
   secret-like added lines, conflict markers, binary blobs, >1 MiB files);
4. validates the message (required, ≤100 characters, no attribution wording);
5. runs `git commit` with the given `-m` parts, then prints the hash, subject,
   file/line count, and any files that changed during the commit.

Exit code `0` means committed (or nothing to commit, for which it exits without
creating an empty commit). Exit `1` means a safety check blocked it; exit `2`
means a usage or environment problem. On any failure nothing is committed and
the index is left staged.

### 3. Handle the outcome

- **Exit `0`:** report the hash, subject, and file count. If the script printed
  "Nothing to commit", say so — do not invent a commit.
- **Exit `1` from screening:** read the listed findings. Unstage what does not
  belong (`git restore --staged <path>`), add a `.gitignore` pattern only when
  the file is clearly a local artifact, and tell the user. If it looks like a
  real credential, stop and ask before doing anything else.
- **Exit `1` from hooks:** fix the underlying problem, re-run the script.
- **Exit `2`:** correct the message or environment (identity, branch, in-progress
  operation) and re-run.

## Failure handling

| Situation | Action |
| --- | --- |
| Screening flags a likely real secret | Stop, report the path and pattern; ask before committing |
| Pre-commit hook fails | Read the hook output, fix the underlying problem, re-stage, re-run |
| Hook is missing or broken | Report it; never bypass with `--no-verify` |
| Huge artifact picked up by `git add -A` | Unstage it, add a `.gitignore` entry, re-run |
| Nothing staged | Report that there is nothing to commit; do not create an empty commit |
| Detached HEAD / mid-rebase | Stop; the script refuses — ask the user how to proceed |

## Reference

- `scripts/commit.sh` — the deterministic entry point described above; `--help`
  lists its flags.
- `scripts/preflight.sh` — read-only staged-change screening on its own; exits
  `1` on findings, `0` when clean, `2` when the environment is unusable. Safe to
  run repeatedly.
- `git status --short --ignored` — confirms whether flagged files are ignored.
